# E7 capability 4: `taliesin lsp` hover (design + plan)

**Date:** 2026-07-21 · **Status:** approved, lean process (combined design+plan) ·
**Follows:** the E7 diagnostics slice, go-to-definition, and document-outline capabilities
on the same `taliesin lsp` server.

## Goal

Add `textDocument/hover` to `taliesin lsp` so any LSP editor shows the meaning of the token
under the cursor, exactly as the VS Code companion's `hover-provider.ts` does today:

- **`@fig-2`** (cross-reference) → `**Figure 2** — \`@fig-2\`` — the rendered label + number.
- **A front-matter key** (`echo:` under `execute:`) → `` `echo:` (under `execute:`) `` +
  its one-line documentation.
- **`[@smith2020]`** (citation) → the raw BibTeX entry as a ```bibtex code block.

Read-only, offline, navigates-never-writes. A port of the companion's `hover.ts` +
`hover-provider.ts` into the editor-agnostic server, reusing the `classify_target`
foundation the go-to-definition capability already built.

## Where the data comes from (all Rust-authoritative, all reused)

The companion resolves hover content from `taliesin vocab`/`symbols` + the `.bib`. In-process
the server reaches the same sources directly, and more precisely, because it renders the
**live buffer** rather than the on-disk file:

- **xref label + number.** Render the buffer (`render_document_with_includes_rooted`, the
  same parse-only, kernel-free call `symbols_json` uses) → `RenderedDoc::xref_numbers`
  (`id → "2"` / `"2.1"`). The prefix→label map (`fig` → `Figure`) comes from
  `vocab::vocab()["xrefPrefixes"]` (built from the `pub(crate)` `cite::XREF_LABELS`, so the
  public vocab is the only cross-crate path). Detail = `{label} {number}`. If the id is not a
  numbered xref target in the buffer, no hover (say nothing rather than guess), matching the
  companion. Because the render is of the live buffer, there is no on-disk staleness gap, so
  the companion's `harvestAnchorIds` "cross-reference target" fallback is unnecessary here.
- **front-matter key description.** `vocab::vocab()["frontmatter"]["keys"]` (top level) or
  `["frontmatter"]["nested"][parent]` (a key under a recognized nested parent) →
  `{name, description}`. No match → no hover.
- **cite → BibTeX entry text.** A new `lsp_nav::bib_entry_text(bib, key)` — the brace-balanced
  port of the companion's `bibEntryFor` — over the first front-matter `.bib`
  (`frontmatter_bib_paths`) that defines the key. No entry → no hover.

## Architecture

- **`crates/server/src/lsp_nav.rs`** — add `bib_entry_text(bib, key) -> Option<String>`
  (brace-balanced entry slice), refactoring a shared `bib_entry_offset(chars, keyc)` out of
  the existing `bib_entry_site` so both stay consistent. Pure, unit-tested.
- **`crates/server/src/lsp.rs`** — advertise `hover_provider: Some(Simple(true))`; route
  `HoverRequest::METHOD` in `handle_request` to a new `resolve_hover(docs, &params) ->
  Option<Hover>`; respond with the `Hover` (Markdown `MarkupContent` + the token `range`) or
  `null`. Include/None targets get no hover.
- Position offsets stay char-based (UTF-16 for ASCII), consistent with the prior capabilities.
- The buffer is rendered on demand per hover (parse-only; hover is infrequent). No caching in
  this cut; add it later only if a real doc proves it slow.

### Commit 3 — `textDocument/hover`

- Advertise `hover_provider` in `server_capabilities`.
- `resolve_hover`: `classify_target` →
  - `Xref { id, start, end }` → render buffer; `xref_numbers.get(id)` + vocab label for the
    prefix; `Hover(**{label} {number}** — \`@{id}\`, range on the hover line)`; else `None`.
  - `FrontmatterKey { key, parent, start, end }` → vocab keys/nested description; scope suffix
    ` (under \`{parent}:\`)` when nested; `Hover(\`{key}:\`{scope}\n\n{description})`; else `None`.
  - `Cite { key, start, end }` → first bib path whose `bib_entry_text` hits →
    `Hover(```bibtex\n{entry}\n```)`; else `None`.
  - `Include { .. } | None` → `None` (include is go-to-definition only, mirroring the companion).
- Route `HoverRequest::METHOD` in `handle_request`.
- Failing integration pins (in-process `Connection::memory()`): hover on `@fig-1` in a doc
  with `# Title {#fig-1}` → contains `Figure 1`; hover on a front-matter `title:` key →
  contains the key's description; hover on `[@smith2020]` with a temp `.bib` → a `bibtex` code
  block containing the entry.

## Verify

`cargo test -p taliesin-server` (serial if the exec/kernel flake trips), `cargo fmt --check`,
`cargo clippy -p taliesin-server --all-targets`, and a real-process smoke: spawn `taliesin lsp`,
initialize + didOpen + `textDocument/hover` on an xref, a front-matter key, and a citation;
confirm each `Hover` on stdout. Then narrow the backlog E7 item (hover shipped).

## Non-goals

Completion, rename, quick-fix code-actions (later capabilities on this server); hovering an
include path (definition-only, as in the companion); per-document render caching; companion
migration to `vscode-languageclient`.
