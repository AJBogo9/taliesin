## What the rehearsal found

Three defects, none of which any local gate could see. That is the whole case for having
done this before the flip rather than after.

### 1. The documented rehearsal path did not work (fixed, commit 626ec7e7)

Every job in both workflows carried `if: github.event.repository.private != true`. The
`workflow_dispatch` event payload includes `repository`, so on a private repo a manual
dispatch skipped every job and returned a green checkmark certifying nothing. Meanwhile
`ci.yml` itself claimed "`workflow_dispatch` below exists FOR that rehearsal and for nothing
else", which was therefore false.

The first rehearsal (runs 32381438373 / 32381441259) could only proceed by deleting the eight
guard lines on a throwaway branch, which in turn broke
`docs_do_not_promise_a_ci_that_enforces_gates` in the `test` job. That failure was an artifact
of the method, not a defect in the tree.

Fixed by making the guard two-part:
`if: github.event.repository.private != true || github.event_name == 'workflow_dispatch'`.
Automatic triggers still skip on a private repo, so the billing protection is intact, and
`crates/core/tests/stale_docs.rs` counts the substring, so its guard-count assertion is
unaffected. Verified: run 32384105416 executed its jobs with the guards present, which the
same dispatch could not do before.

### 2. The kernel job's cell timeout made one test unpassable (fixed, commits 626ec7e7, e58fe54c)

`ci.yml` pinned `TALIESIN_CELL_TIMEOUT: "3"` job-wide. The test
`a_first_build_publishes_the_body_before_the_cells_finish` uses a fixture cell that runs
`time.sleep(8)` and then asserts the finished build contains its output. Three is less than
eight, so the cell was always interrupted and the assertion could NEVER pass under CI's
environment. The comment justifying the 3 claimed "every other kernel cell here finishes in
well under 3s", which was false for exactly that cell.

Raised to 30 and the comment corrected. The 60s and 120s runaway fixtures are unaffected:
the four in `kernel.rs` override `cell_cap`/`silence_cap` directly on the Kernel struct, and
the one in `exec.rs` is protected because its manual `interrupt_pid()` fires within tens of
milliseconds of a marker file appearing, far ahead of any wall-clock cap.

Verified: the `kernel` job went from failure (32381438373) to success (32384105416).

### 3. A hand-authored User Guide asset had never been committed (fixed, commit b1ed1491)

`docs/guide/using/writing.tmd:112` references `figures/loss.png`, and `.gitignore`'s
`**/figures/` rule ignored every `figures/` directory in the tree. The rule exists for figures
GENERATED by code cells, and it is right for `loss.pdf`, which `docs/guide/using/code.tmd:166`
really does produce with `fig.savefig`. But `loss.png` is hand-authored and generated by no
cell anywhere. It had been on the author's disk since 2026-08-01 and was never tracked.

**This is the most consequential of the three.** The User Guide is one of four sites that get
deployed publicly. In any fresh clone the image is absent, so the published guide would carry
a broken image and no contributor could build the docs. Neither `.githooks/pre-push` nor
`./tools/gates.sh` can catch this class of defect, because both run against the author's own
working tree where the file is present. Only a fresh-clone build finds it, which is exactly
the value `ci.yml`'s own header comment claims for CI.

Fixed by restructuring the rule to `**/figures/*` plus a negation for this one file (a negated
child cannot override an excluded parent directory), and tracking the file. Verified by a cold
fresh-clone build of `docs/guide --check-only`, and then by run 32385768089.

## Verdict

**Both workflows now pass end to end.** CI 32385768089: six of six jobs green. Release
32384108999: four of four green, including both macOS targets. This is the first fully green
CI run in the project's history.

## What this does NOT establish

- The macOS binaries were built in CI but never executed on macOS hardware. The matrix proves
  they compile and package, not that they run.
- `release.yml` has still never fired on a real `v*` tag. Both its runs were
  `workflow_dispatch` on a branch, so the tag-derived naming path is unexercised and artifacts
  were named `taliesin-rehearse-2-<target>` rather than `taliesin-v1.0.0-<target>`.
- No release was published. The rehearsal proves the build and package steps, not the upload
  to a real GitHub Release.
- CI ran against branch `rehearse-2`, not against the tree that will actually flip. It must be
  re-run against the final tree, which is Task 10 Step 4 of the publication-prep plan.
