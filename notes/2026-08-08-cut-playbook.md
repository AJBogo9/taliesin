# Cut playbook: the file-level removal steps

**Generated 2026-08-08** from the adversarial adjudication behind
[the scope ruling](2026-08-08-scope-ruling.md). Read that first: it holds the
verdicts, the corrections, and the judgement calls. This file holds only the mechanics.

**How to use this.** One wave per branch per session. Read the ruling, read this wave's
section, execute, run `./tools/gates.sh`, commit, then tick the wave off in
[CUT-PROGRESS.md](CUT-PROGRESS.md). Do not run two waves in one session; the point of
the sequencing is that each wave lands green on its own.

> **SCOPE QUALIFIERS ARE LOAD-BEARING.** Some bundles are split across waves. Where a
> wave's heading carries a qualifier like *(step 1 only: dead code)*, that wave takes
> **only** that slice, and the full step list reproduced beneath it is the bundle's
> complete plan for reference. Executing the whole list in the wrong wave is the main
> way to break this plan. The bundle's full removal happens in the wave marked
> *(full bundle)*.

**Line numbers are from a read of `f6dee87d` and drift the moment you start editing.**
Treat them as a map, not a script: grep for the symbol, do not seek to the line. Where
a step names a symbol and a file, the symbol is authoritative.

**Standing rules for every wave**
- Branch first; `main` is protected by `.githooks/pre-push`.
- A retired div class needs a `RETIRED_DIV_CLASSES` entry, a retired front-matter key a
  scoped `RETIRED_KEYS` entry, a retired verb a `RETIRED_COMMANDS` entry. Without one a
  leftover gets silence instead of a diagnostic.
- Never delete a corpus pin ahead of the feature it guards.
- Verify with `./tools/gates.sh`, not bare `cargo test` (which skips silently).
