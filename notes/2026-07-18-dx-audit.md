# Developer-experience audit — 2026-07-18

> Trigger: shell tab-completion just shipped; "what other features in that vein would
> make the DX the best possible, and how discoverable is the tool without docs?"
> Method: 2 internet-research passes (DX/productivity frameworks + CLI/dev-tool
> discoverability patterns, sourced) + 2 read-only codebase audits (full DX-surface
> map + error/feedback-loop audit) + 4 persona workflow simulations
> (Quarto-refugee academic, weekly technical blogger, conference-speaker deck author,
> headless AI agent), each grounded against the real source. Companion to `backlog.md`
> / `ROADMAP.md`; index this in `AUDITS.md`.

## Verdict

Taliesin's DX is already **well above the median dev tool** on the things that are
hardest to build: a sub-second, state-preserving, block-level feedback loop; click-to-source;
kernel-unavailable errors that name the interpreter path + env var + fix; "did you mean"
on unknown commands/flags/kinds/front-matter keys; a genuinely strong headless agent
surface (`read`/`map`/`symbols`/`vocab`/`schema`/`check --format json`); a distinctive
default deck identity; and a speaker view that **matches or beats reveal.js** (notes +
step-aware next-slide + elapsed timer + wall clock + live sync). This audit is therefore
not "fix a broken tool"; it is "close a short, unusually consistent list of gaps that
keep a very good tool from feeling effortless."

**One finding dominates every persona and both codebase audits.** Almost all of the
recommendations below are *surfacing capability the tool already has* in a place the
user isn't looking, not net-new engineering.

---

## THE dominant finding: the preview→publish validation cliff

Taliesin has excellent, located, "did-you-mean"-carrying validators for broken internal
links, missing images/assets/media, duplicate heading ids, and dangling cross-references.
They run in `build` and `check`. **They do not run in the live preview** — the surface
where authoring actually happens — and the multi-page *site* preview (the primary
tech-blog workflow) validates even less than a throwaway single-doc preview
(`serve_site` never calls `validate_xrefs` and never runs `page_static_diagnostics`).

The diagnostics→dev-menu→click-to-source *transport already exists* and is used by the
render-pass warnings; the static validators simply aren't wired onto the serve path
(they live in `check.rs:112 page_static_diagnostics`, called only from `build`/`check`/`publish`).

Result: the loop protects the author's flow right up to the moment they're most rushed,
then breaks hardest.

- **Priya** (academic) typo'd `@fig-umpa` and pointed an image at a wrong filename; the
  preview showed a silent dead link + a broken-image glyph, no warning. She shipped a
  "finished" draft with both errors and only found them by running `check` by hand later.
- **Marcus** (blogger) linked an old post with a wrong slug and referenced a screenshot
  with the wrong filename; both looked fine in preview; both surfaced only when
  `publish --strict` failed at 10pm, minutes after he thought he was done and had already
  context-switched out of writing. He called this "the single biggest flow-killer in my
  weekly loop… worth more than every other item on the list combined."
- **Lena** (speaker) typed reveal.js's `:::: {.columns}` from muscle memory; it *silently
  degraded to a plain stacked div* (the fall-through arm in `divs.rs`; real syntax is
  `{layout-ncol=2}`), looked plausible in a quick scroll, and blew up her before/after
  slide **on the projector in front of 200 people**.
- **The agent** couldn't tell its `{js}` chart even executed (see agent section).

### Fix (this is recommendation #1 below, stated once, in full)
Run `page_static_diagnostics` + `validate_xrefs` on **both** serve paths behind a small
debounce; bring `serve_site` to parity with `serve`; surface results in the existing
dev-menu diagnostics list with click-to-source; add a **red-dot "audit" badge** on the
collapsed `◇</>` button (Astro dev-toolbar pattern) so the signal comes to the author
instead of waiting behind a click. Locate + browser-surface the `_site.yml` unknown-key
warnings (today console-only, unlocated) and warn on unknown `:::` classes with a
"did you mean" (today silent). Make cross-page link checking incremental enough for the
hot loop — that's the only real engineering; the rest is wiring.

### Design questions (owner decides; not recommendations)

- **Terminal hotkeys** (Vite `r/o/u/c/q`): deliberately absent — interactivity was moved
  to the browser dev menu on purpose. Cheap middle path: one banner line pointing at the
  `◇` menu, so a Vite user who presses `h` isn't met with silence (✍️🎤 both did).
- **Deck sharing/publish**: the Share QR encodes `localhost:PORT` (useless off-laptop) and
  `build` yields a file the user must host themselves. Is a one-command deck publish in scope? (🎤)
- **Presenter laser/spotlight + auto-advance** (reveal.js reflexes). (🎤)
- **PDF/print**: already sanctioned in ROADMAP (Pillar IV / Wave 5, derived from HTML).
  #11 is the interim guardrail, not a substitute.

## Research principles behind the ranking (sourced)

The DevEx framework (Noda, Storey, Forsgren, Greiler, ACM Queue 2023) reduces productivity
to three improvable frictions — **feedback loops, cognitive load, flow state** — and this
audit maps cleanly onto them:

- **Feedback loops** (Cochran's loop-latency table; Parnin & Rugaber's interruption study:
  only ~10% of sessions resume coding in <1 min after an interruption). Taliesin's core bet
  is already here. The gap is *diagnostic* feedback (#1): the fast loop is silent about the
  errors the author most needs to see while writing.
  — martinfowler.com/articles/developer-effectiveness.html · link.springer.com/article/10.1007/s11219-010-9104-9
- **Cognitive load / sensible defaults / progressive disclosure** — zero-config that "just
  renders," "did you mean" instead of doc-hunts, schema-driven editor validation.
  — vite.dev/config · nngroup.com/articles/4-principles-reduce-cognitive-load
- **Flow state** — never break context on reload (Taliesin's block-diff preserves scroll;
  keep it across structural reloads too), immediate cause→effect (Bret Victor "immediate
  connection").
- **Error messages that teach** — the Rust/Elm anatomy (what/where/why/fix + a link, smallest
  span, plain language, "did you mean"). Taliesin's *wording* already follows this; the deficits
  are almost entirely about **where** the good messages run.
  — rustc-dev-guide.rust-lang.org/diagnostics.html · elm-lang.org/news/compiler-errors-for-humans
- **Time-to-first-success & scaffold-as-teacher** — a working starter teaches the format
  better than docs (#10). — moesif.com/blog/technical/api-product-management/What-is-TTFHW
- **Discoverability catalog** (exemplars): Vite/Next startup banner + press-h hotkeys;
  Vite/Next in-page error overlay with open-in-editor; **Astro dev-toolbar "Audit" app**
  (inline a11y/perf/link issues + red-dot badge) — the single closest analogue to #1/#2;
  `?` shortcut overlay; `flutter doctor`/`quarto check`; `rustc --explain`; JSON-Schema config
  autocomplete; gh/fzf dynamic completion; interactive `bun init`/`quarto create` wizards.
  — clig.dev · docs.astro.build/en/guides/dev-toolbar · cli.github.com/manual/gh_completion

Skeptic notes carried from the research: the widely-repeated "50% faster with instant
feedback," "82% of productive time lost to interruptions," and "progressive disclosure
20–40% faster" stats are folklore (no locatable primary) — do not cite. The ACM DevEx/SPACE
primaries 403 the fetcher; levers were taken from the authors' own getDX/InfoQ write-ups
cross-checked against the abstracts.

## Per-persona friction (highlights; full tables in the run transcript)

- **🎓 Priya (Quarto refugee, first run).** Delights: `new paper` is citation-wired;
  Quarto `#| label:`/`#| fig-cap:` cell-options work *verbatim*; click-to-source sold her.
  Worst moment: `build methods.tmd methods.pdf` succeeded and wrote corrupt HTML-as-PDF,
  then she learned PDF doesn't exist. Also: conda env not auto-detected; errors live in a
  browser button a terminal-first user never looks at.
- **✍️ Marcus (weekly blogger, power user, time-boxed).** Delights: block-level updates
  preserve scroll/expanded state — real flow. Worst: the validation cliff (broken image +
  wrong-slug link found only at `publish --strict`). Also: no `--draft` on `new post`;
  click-to-source undiscovered until he idly clicked `◇`; wanted Cmd-K to *do* things.
- **🎤 Lena (deck author, pre-talk).** Delights: distinctive default identity; speaker view
  matches/beats reveal.js; magic-move; auto-fit. Worst: reveal.js `.columns` silently
  degraded and broke a slide on the projector; the scaffold taught none of the deck's powers
  (she found them by reading `corpus/deck.tmd`).
- **🤖 Agent (headless authoring).** Delights: `map`'s xref graph lets it pick cross-ref
  targets without opening files; stable codes + `suggestion.replacement`; drift-proof
  `AGENTS.md`. Worst: it cannot see whether its chart executed — `read` shows source, `check`
  is static, `build` runs python/r only, `{js}` is never server-run. Also: `check` exits on
  any severity (warnings block); no `--explain`; the CSV→figure idiom is the one thing not in
  `vocab`.

## Suggested sequencing

1. **#1 (live validation + audit badge)** — one change, every persona benefits, mostly wiring.
2. **#2 + #3 + #10** (first-run hints, schema auto-wire, teaching scaffolds) — the cheapest
   discoverability wins; each is S and each converts an existing capability from hidden to used.
3. **#5 + #11** (unknown-`:::` warning, friendly `.pdf` reject) — kill the two silent-failure
   traps that most damage trust.
4. **#4 + #6 + #8** (`doctor`, `--explain`, command palette) — the heavier discoverability tier.
5. **#17–#19** (agent headless-output, exit-gating, recipes) — the AI-native depth play;
   #18 is S and worth pulling forward.

Everything in Tier 0–1 and most of Tier 2 is *surfacing existing capability*. The tool is
closer to "effortless" than the gap count suggests.
